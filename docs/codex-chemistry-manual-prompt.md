- `scripts/extract-chemistry-230.py` は実行しないでください。不要になったので、最後に削除してください。

  - `problem_number` と `sub_label` の列
  - 「問題番号 ○〜○」の範囲指定を本の番号で絞り込む処理

作業を始める前に `AGENTS.md` を読んでください。コードを書く前に、`node_modules/next/dist/docs/` の該当ページを確認すること。

## 1. 問題データを手入力する
- **入力先**：`data/manual-import/chemistry-230.txt`（テンプレート作成済み）
  - 項目の意味・書き方のルール・記入例は、ファイル冒頭のコメントにあります。**それに厳密に従ってください。**
  - `data/` は git の管理外です。著作物なので、コミットしないでください。
- **見る PDF**
  - 問題編：`data/化学頻出スタンダード問題230選_問題編_001-079.pdf`、`_080-158.pdf`
  - 解答解説編：`data/化学頻出スタンダード問題230選_解答解説編_159-251.pdf`、`_252-345.pdf`
  - ファイル名の数字は PDF のページ範囲です。全体版は `sankosho/化学頻出スタンダード問題230選 .pdf` にあります。
- **進め方**
  1. まず**問題1〜20だけ**を入力して止まり、報告してください。利用者が本と見比べて、書き方を確認します。
  2. OK が出たら、30問ずつ進めます。区切りごとに、入力した小問の数と飛ばした問題を報告してください。
- **問題を飛ばすとき**：図が必須などの理由で出題しない場合は、その問題番号の位置に、コメント行で理由を残してください。
  - 例：`# N:57 飛ばし：装置図を見ないと答えられない`
- **読み間違いに注意する文字**：問題文を写すときは、次の取り違えに特に注意してください。
  - 数値、単位、指数（10^-3 など）、化学式の数字（下付き）、イオンの価数、矢印（→、⇄）

## 2. 取り込みスクリプトをテンプレートに対応させる
`scripts/import-chemistry-230.mjs` が、`chemistry-230.txt` を直接読めるようにしてください（JSON に変換する手順をなくす）。
- **使い方**：`node scripts/import-chemistry-230.mjs data/manual-import/chemistry-230.txt --dry-run`
- **書式チェック**：パースした時点で、次の問題があればエラーにして、該当する行番号を表示する。
  - 必須項目が無い
  - `N` が 1〜230 の範囲外
  - `T` が recall / solve 以外
  - `T: solve` の計算問題に `U` が無い
- **途中まででも本番に入れられるようにする**：入力が途中でも取り込めるようにし、何度でもやり直せるようにしてください。誤りの多い古い問題を残すより、確認済みの問題だけのほうがよい、という判断です。
  - 実行のたびに、化学230選の問題を**テンプレートの内容で丸ごと置き換える**。
- **習熟度の引き継ぎ**
  - 2回目以降の取り込みでは、`(problem_number, sub_label)` が同じ問題の、ID と習熟度（`oral_exam_mastery`）を引き継ぐ。
  - 問題番号の無い古い問題の習熟度は、削除してよい。
- **AI の自動点検で書き換えさせない**：取り込んだ問題には `reviewed_at` を入れる。セッション開始時の自動点検（`src/app/api/oral-exam/session/route.ts` の `needsQuestionReview`）は、未点検の問題を AI で書き換えることがあります。確認済みのデータが書き換えられないよう、点検の対象から外してください。
- 既存のバックアップ作成と `--dry-run` の仕組みは、そのまま残してください。

## 3. 採点の基準を保存して、AI 採点に使う
`oral_exam_questions` に、次の列を `ensureColumn` で追加してください（`src/lib/db.ts`）。

| 列 | テンプレートの項目 | 内容 |
|---|---|---|
| `question_kind TEXT` | `T` | `recall` / `solve`。空なら従来どおり自動判定 |
| `speech_text TEXT` | `R` | 読み上げ用の問題文。空なら `prompt` を読む |
| `grading_json TEXT` | `K`, `OK`, `NG`, `U`, `SIG` | `{ requiredKeywords: string[], acceptedVariants: string[], misconceptions: string[], numericAnswer: string, significantFigures: number \| null }` |

- **出題の種類**：`src/lib/oral-exam-mastery.ts` の `questionKind()` は、`question_kind` があればそれを優先する。
- **読み上げ**：`src/app/student/oral-exam/page.tsx` で、音声で読み上げるときだけ `speechText` を使う（「もう一度読む」ボタンも含む）。画面には、これまでどおり `prompt` を表示する。
- **採点への反映**：`src/app/api/oral-exam/attempt/route.ts` で、採点 AI に渡す情報に採点基準を足す。
  - 渡す情報：「必須キーワード」「正解として認める言い換え」「不正解にすべき誤り」「正しい数値と単位」「有効数字」。空のものは渡さない。
  - システムプロンプトに、次の方針を足す。
    - 必須キーワードが欠けていたら不正解。ただし、同じ意味の言い換えは認める。
    - 誤概念に当てはまる回答は不正解とし、改善点でその誤りを具体的に指摘する。
    - 計算問題は、数値と単位の両方が合っていれば正解とする。表記の違い（0.5 と 5.0×10^-1、mol/L と mol·L^-1）は認める。単位が無い・違う場合は不正解。
    - 有効数字の指定がある問題では、桁数が違っていても正解とするが、改善点で指摘する。
- **講師画面**（`src/app/dashboard/oral-exam/books/[id]/page.tsx`）：問題番号・小問・種類・採点基準が見えるようにする。編集までできると、なおよい。
- **ほかの参考書への影響**：これらの列が空の本では、今までと動作が一切変わらないようにすること。

## 守ってほしいこと
- **審査用アカウントの問題集は変えない**：審査用アカウント `s-test-family` には、オリジナルの「体験用サンプル問題集」だけが割り当たる仕組みがある（`ensureReviewSampleBook`）。これを壊さない。
- **コミットしない**：参考書の本文（PDF、`data/` 以下）はコミットしない。
- **完了の条件**：`npx tsc --noEmit`、`npx eslint`、`npm run build` がすべて通ること。
- **ローカルで確認**：ローカルの `data/app.db` で取り込みを実行し、アプリで次の3点を確認する。
  - 「化学230選・問題番号 1〜3」を指定すると、本の問題1〜3だけが出る
  - `R:` を書いた問題は、読み上げ用の文で読まれる
  - 計算問題で単位を付けずに答えると、不正解になる
- **コミットの形**：アプリ側の変更と取り込みスクリプトは、別々のコミットにする。push は利用者の確認後に行う。
- **区切りごとの報告に含めるもの**
  - 入力済みの問題番号の範囲と、小問の数
  - 飛ばした問題と、その理由
  - 本番で実行するコマンド（1行ずつ。最初は `--dry-run`）
