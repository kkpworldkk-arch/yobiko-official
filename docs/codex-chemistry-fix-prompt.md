# Codex への依頼：化学230選の問題データ作り直しと「問題番号」の修正

## 背景
このリポジトリは、医学部予備校「滝原塾」の学習アプリです（Next.js 16 と SQLite。本番は Render）。
- App Store で公開中で、生徒が毎日使っています。
- 「AI口頭試問」は、参考書の問題を一問一答で出題し、AI が採点する機能です。
- 作業を始める前に `AGENTS.md` を読んでください。この Next.js は通常版と API が異なるため、コードを書く前に `node_modules/next/dist/docs/` の該当ページを確認すること。

参考書「化学頻出スタンダード問題230選」（`oral_exam_books.title` が完全一致）の問題データに、生徒から2つの不具合報告が来ています。

1. **問題番号が本と合わない**
   - 出題範囲の「問題番号 ○〜○」は、本の問題番号（1〜230）ではありません。取り込み順の通し番号 `order_index + 1` で、化学は約1600問あります。
   - 該当コードは `src/lib/db.ts` の `matchesOralExamFilters` と、範囲の選択肢を作っている部分です。
   - そのため、生徒が「問題番号 1〜10」を指定しても、本の問題1〜10は出ません。
2. **問題・答えが間違っている、読み取れていない**
   - 以前、OCR で取り込んだため、誤読が多数残っています。例：
     - 「冷蔵を必要としたときにくだえる混合物は…」のように、意味の通らない問題文
     - メタンについて「空気より密度が大きい」と答えている（誤り）
     - `category` の章名がばらばら
     - `source_page` が空

## やってほしいこと

### A. 問題データを PDF から作り直す（Claude のビジョン機能を使う）
- **元の PDF**（`/data/` と `/sankosho/` は git 管理外。このPC上にだけある）
  - `sankosho/化学頻出スタンダード問題230選 .pdf`（ファイル名の「選」の後に半角スペースがある）
  - 分割版：`data/化学頻出スタンダード問題230選_問題編_001-079.pdf`、`..._080-158.pdf`、`..._解答解説編_159-251.pdf`、`..._252-345.pdf`（ファイル名の数字は PDF のページ範囲）
- **流用できる既存のもの**：`scripts/import-reference-questions.py`
  - ページ画像を Claude に送って抽出する仕組みと、プロンプトの失敗事例集は流用してください。
  - API キーは `.env.local` の `ANTHROPIC_API_KEY` を使います。
  - モデルは `claude-sonnet-5-5` にしてください（既存スクリプトの古いモデル ID は使わない）。
- **作り方**：問題編のページと、それに対応する解答解説編のページを**両方**読み、**問題と答えを照合してから**一問一答を作ること。問題編だけから答えを推測するのは禁止です。
- **1件ごとに持たせる項目**
  - `problemNumber`：本の問題番号（1〜230の整数）。必須。
  - `subLabel`：小問の番号（例 `(1)`, `(2)`, `ア`）。小問がなければ空文字。
  - `chapter`：本の目次どおりの章名。例「第1章 物質の構成」。同じ章は**一字一句同じ表記**にそろえる。
  - `sourcePage`：問題が載っている本のページ番号（PDF のページ番号ではなく、紙面に印刷された番号）。
  - `prompt`：音声で読み上げて意味が通る問題文。図やグラフを見ないと答えられない問題は出さない。選択肢問題は、選択肢を問題文に含めるか、記述式に言い換える。
  - `modelAnswer`：解答解説編に基づく正解（要点）。計算問題は数値と単位。
- **出力先**：`data/chemistry-230-questions.json`（git 管理外。著作物なのでコミットしない）。並び順は `problemNumber`、`subLabel` の順。
- **途中再開**：途中で止まっても続きから再開できるように、進捗ファイルを残す。
- **品質チェック**：完了後、ランダムに30問を選び、PDF と突き合わせた結果を `data/chemistry-230-check.txt` にまとめる。
  - 問題番号の欠け（1〜230のうち1問も無い番号）も一覧にする。
  - 欠けた番号は、図が必須などの理由で出題できないもの以外は、抽出し直す。

### B. 本番 DB に入れ替えるスクリプト（Render の Shell で実行する）
本番の DB は Render 上の `/var/data/app.db` です（環境変数 `DATA_DIR`）。ローカルの `data/app.db` とは内容が違います。本番には講師の編集や生徒の学習記録があります。
- `scripts/import-chemistry-230.mjs` を作ってください（node:sqlite を使う。既存の `scripts/reset-review-account.mjs` の書き方を参考に）。
  - **使い方**：`node scripts/import-chemistry-230.mjs <jsonのパス>`。`--dry-run` を付けたときは、件数と差分の要約だけを表示する。
  - **最初にバックアップ**：実行前に DB を `app.db.bak-<日時>` にコピーする。
  - **入れ替え**：1回のトランザクションで、化学230選の `oral_exam_questions` を新しいデータに置き換える。`order_index` は `problemNumber`、`subLabel` の順に0から振り直す。
  - **習熟度は可能な限り引き継ぐ**：古い問題と新しい問題が「問題番号が同じで、問題文がほぼ同じ」なら、`oral_exam_mastery` の question_id を新しい ID に付け替える。対応が取れない古い問題の習熟度は削除する。
  - **消さないもの**：`oral_exam_attempts`（回答履歴。問題文はコピーで持っている）。`oral_exam_assignments`、`oral_exam_sessions`、生徒・講師のデータ。
- **送り方**：JSON はリポジトリに入れないので、本番への受け渡しは利用者が手動で行う（magic-wormhole で送る想定）。その手順を、最後にコマンド1行ずつで説明すること。

### C. アプリ側：「問題番号」を本の問題番号にする
- `oral_exam_questions` に `problem_number INTEGER` と `sub_label TEXT` の列を追加する。`src/lib/db.ts` の既存の `ensureColumn` の仕組みを使い、既存 DB でも自動で列が増えるようにする。
- 出題範囲の「問題番号 ○〜○」は、`problem_number` があればそれで絞り込む。無い本（ほかの参考書）は、今までどおり `order_index + 1` を使う。
- 範囲を選ぶ選択肢も、`problem_number` がある本では本の番号（1〜230のうち実在する番号）を出す。
- 出題中の画面と回答履歴に「問題 12 (2)」のように本の番号を表示する（`src/app/student/oral-exam/page.tsx`）。
- 講師画面の問題編集（`src/app/dashboard/oral-exam/` 以下）でも、問題番号が見えて編集できるようにする。

## 守ってほしいこと
- **審査用アカウントの問題集は変えない**：`s-test-family`（App Store 審査用アカウント）には、オリジナルの「体験用サンプル問題集」だけが割り当たる仕組みがある（`ensureReviewSampleBook`）。これを壊さない。
- **コミットしない**：参考書の本文（PDF・JSON・抽出テキスト）はコミットしない。
- **完了の条件**：`npx tsc --noEmit`、`npx eslint`、`npm run build` がすべて通ること。
- **ローカルで確認**：ローカルの `data/app.db` で、`scripts/import-chemistry-230.mjs` を一度実行する。そのあと、アプリで「化学230選・問題番号 1〜3」を指定して、本の問題1〜3だけが出ることを確かめる。
- **コミットの形**：アプリ側（C）とスクリプト（B）は、別々のコミットに分けてください。push は利用者の確認後に行う。
- **最後の報告に含めるもの**：
  - 抽出した問題数
  - 欠けている問題番号
  - 品質チェックの結果
  - 本番で実行するコマンド（1行ずつ）
